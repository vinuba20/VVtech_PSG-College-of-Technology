\## 2. Project Title



\*\*Diabetes Digital Twin: Predicting Hyperglycemia 2 Hours Ahead by Fusing EHR and CGM Data\*\*



\## 3. Problem Statement and Healthcare Use Case



India has one of the largest Type 2 diabetes populations in the world. Most patients see a doctor only a few times a year, and in between, dangerous glucose spikes go unnoticed until they cause damage. Care is reactive.



\*\*Our solution:\*\* a Digital Twin of a Type 2 diabetes patient. It is a virtual replica that combines:



\- \*\*Static data:\*\* the patient's health record (age, BMI, HbA1c, years with diabetes, insulin use)

\- \*\*Dynamic data:\*\* continuous glucose monitor (CGM) readings every 5 minutes



The model predicts whether the patient's glucose will exceed \*\*180 mg/dL within the next 2 hours\*\*, so the patient and doctor can act before the spike happens (diet change, activity, insulin timing).



A doctor dashboard shows the live glucose trend, the risk score, an alert level, and an explanation of \*why\* the model made its prediction.



\## 4. Technical Stack and Model Details



| Component | Technology |

|---|---|

| Language | Python 3 |

| Data handling | pandas, NumPy |

| ML model | XGBoost (gradient-boosted decision trees) |

| Evaluation | scikit-learn |

| Explainability | XGBoost per-prediction feature contributions (SHAP-style) |

| Dashboard | Streamlit, Plotly |



\*\*Data fusion:\*\* each CGM window is joined with the patient's EHR record, giving 16 features per prediction.



\- \*\*Sensor features:\*\* current glucose, glucose 15 min / 30 min / 1 h ago, rate of change (15 and 30 min), 1-hour mean, standard deviation and max, time of day (sine/cosine)

\- \*\*EHR features:\*\* age, BMI, HbA1c, years with diabetes, on insulin (yes/no)



\*\*Target:\*\* 1 if glucose exceeds 180 mg/dL at any point in the next 2 hours, otherwise 0.



\*\*Validation:\*\* the train/test split is done \*\*by patient\*\*, so the model is tested on patients it has never seen.



\### Results (synthetic test set)



| Metric | Score |

|---|---|

| AUC | 0.985 |

| Accuracy | 0.935 |

| Recall | 0.880 |

| Precision | 0.881 |



> \*\*Honest note:\*\* the data is synthetic with regular meal patterns, so these scores are optimistic. Real-world performance would be lower and would need validation on real, anonymized clinical data.



\### Data Sources (Privacy-Compliant)



Per the challenge sandbox rules, \*\*no real patient data is used.\*\* Both streams are fully synthetic and generated by `generate\_data.py`:



\- \*\*EHR:\*\* 100 synthetic patients (age, BMI, HbA1c, diabetes duration, insulin use)

\- \*\*CGM:\*\* 14 days of readings every 5 minutes per patient, with baseline glucose linked to HbA1c and simulated meal spikes at breakfast, lunch and dinner

\## How to Run



```bash

\# 1. Install dependencies

pip install pandas numpy scikit-learn xgboost streamlit plotly joblib



\# 2. Generate synthetic data

python generate\_data.py



\# 3. Train the model

python train\_model.py



\# 4. Launch the doctor dashboard

streamlit run app.py

```

\## Limitations and Future Work



\- Trained on synthetic data only; needs validation on anonymized real-world datasets (e.g. MIMIC-IV, open CGM datasets)

\- Add more sensor streams (sleep, heart rate variability, step count)

\- Add meal and insulin logging for personalized treatment suggestions

\- Personalize the model per patient over time

\- Extend to hypertension and cardiovascular risk



\*This is a research prototype and is not intended for clinical use.\*
